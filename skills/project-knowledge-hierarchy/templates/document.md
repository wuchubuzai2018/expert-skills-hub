# 业务文档模板（含 YAML 头部）

## 用途

所有**非 `index.md`** 的具体业务文档必须使用本模板：以 YAML 头部元数据开头，再写正文。AI 在生成业务文档时必须严格遵守该模板。

## 模板

````markdown
---
文档编号: DOC-[层级]-[子目录序号]-[3 位序号]
标题: [文档标题]
类型: [文档类型]
状态: [文档状态]
日期: YYYY-MM-DD
作者: [作者/作者组]
描述: [单句摘要，≤ 80 字]
标签: [标签1, 标签2, 标签3]
---

# [文档标题]

## 正文

[正文内容...]
````

## 字段定义

### 核心 6 字段（必须）

| 字段 | 必填 | 说明 | 取值建议 |
|------|------|------|----------|
| `文档编号` | ✅ | 文档唯一标识，全局不重复 | 格式 `DOC-{层级编码}-{子目录序号}-{3 位序号}`，例如 `DOC-PRJ-01-001`、`DOC-TECH-02-007`、`DOC-AST-04-015` |
| `标题` | ✅ | 文档标题 | 与正文一级标题保持一致 |
| `类型` | ✅ | 文档类型 | `总览` / `索引` / `需求` / `方案` / `设计` / `规范` / `接口` / `测试` / `缺陷` / `决策` / `会议纪要` / 其他 |
| `状态` | ✅ | 文档生命周期状态 | `草稿` / `评审中` / `现行` / `已废弃` |
| `日期` | ✅ | 最近更新日期 | 格式 `YYYY-MM-DD` |
| `作者` | ✅ | 文档作者或作者组 | 个人姓名或团队名，如 `张三` / `架构组` |

### 标准推荐字段（强烈推荐）

借鉴自 Google OKF v0.2 的核心元数据，AI **默认应在生成文档时一并输出**，除非用户明确表示不需要。

| 字段 | 对应 OKF | 推荐度 | 说明 | 取值建议 |
|------|----------|--------|------|----------|
| `描述` | `description` | ⭐⭐⭐ 强烈推荐 | 单句摘要，用于 `index.md` 清单、搜索摘要、预览 | 一句话，≤ 80 字 |
| `标签` | `tags` | ⭐⭐⭐ 强烈推荐 | 跨切面分类标签，便于按主题/模块检索 | YAML 列表，如 `[订单, 收入, 销售]` |

### 扩展可选字段（按需启用）

下列字段借鉴自 Google OKF v0.2，默认情况下**不启用**，仅当用户明确要求"兼容 OKF"或场景需要时（如有规范 URI、需要追踪来源、文档有时效性）才补充输出。

| 字段 | 对应 OKF | 说明 | 取值建议 |
|------|----------|------|----------|
| `资源` | `resource` | 底层资产的规范 URI（表、API、文档链接等） | 绝对 URL 或 Bundle 相对路径 `/path` |
| `来源` | `sources` | 文档引用与上游来源列表 | YAML 列表，每项含 `id`、`resource`、`title`、`author` |
| `过期时间` | `stale_after` | 新鲜度阈值，`now >= 过期时间` 即视为陈旧 | ISO8601 绝对日期，如 `2026-12-31` |

## 层级编码对照

| 层级 | 编码 |
|------|------|
| 项目层 | `PRJ` |
| 技术层 | `TECH` |
| 资产层 | `AST` |

## 占位符说明

| 占位符 | 含义 | 填写示例 |
|--------|------|----------|
| `[层级]` | 所属层级编码 | `PRJ` / `TECH` / `AST` |
| `[子目录序号]` | 该子目录在所属层级中的数字前缀 | `01` / `02` / `05` |
| `[3 位序号]` | 子目录内序号 | `001` / `007` / `015` |
| `[文档标题]` | 文档标题（中文） | `用户中心数据库设计` |
| `[文档类型]` | 见字段定义表 | `设计` / `规范` / `接口` |
| `[文档状态]` | 见字段定义表 | `草稿` / `评审中` / `现行` / `已废弃` |
| `YYYY-MM-DD` | 创建或更新日期 | `2026-08-30` |
| `[作者/作者组]` | 文档作者或团队 | `架构组` |
| `[单句摘要，≤ 80 字]` | 一句话描述本文档目的与受众 | `用户中心核心域的表结构、索引、迁移记录总览` |
| `[标签1, 标签2, 标签3]` | YAML 列表形式的分类标签 | `[用户中心, 数据库, ER, MySQL]` |

## 使用方式

1. 新建业务文档时，先粘贴本模板（默认**标准模板**：核心 6 字段 + 推荐 2 字段）
2. 替换所有占位符（特别注意 `文档编号` 全局唯一）
3. AI 必须主动为 `描述` 与 `标签` 生成合理内容：
   - `描述`：从文档标题与首段提炼单句摘要（≤ 80 字）
   - `标签`：从主题、所属模块、涉及技术栈抽取 3-6 个分类标签
4. 仅当用户明确要求"只要最小集"或"不写描述标签"时，才退化为最小集
5. 扩展可选字段（`资源` / `来源` / `过期时间`）按需补充
6. 编写正文；若源自原始材料，按 `references/raw-layer.md` 在正文末尾添加「## 原始资料」一节
7. 在所属子目录 `index.md` 的「文档清单」表格中追加对应行
8. 当 `状态` 或 `日期` 变更时，同步更新所属 `index.md` 中的记录
````
