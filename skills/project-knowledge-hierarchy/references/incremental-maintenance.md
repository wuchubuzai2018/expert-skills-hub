# 增量维护指引（参考）

## 用途

本文件给出已有文档归档到本结构、或新增文档时的完整流程与决策树，供 AI 在执行增量维护时按需加载。

> 加载说明：SKILL.md 仅保留概要，详细流程与决策树放在本文件中以减少主文件体量。

## 归档四步法

当项目已有文档需要归档到此结构时：

1. **识别文档类型** — 判断属于原始材料还是已成形文档；若是原始材料先走 `references/raw-layer.md` 的提炼流程
2. **确定层级与子目录** — 按下方决策树定位层级（项目层 / 技术层 / 资产层）与子目录
3. **补全元数据** — 为文档添加符合规范的 YAML 头部（若缺失）
4. **移动并登记** — 将文档移动到目标目录，在该子目录 `index.md`「文档清单」中追加条目，并在所属层级 `index.md` 中按需补充

## 新增文档归档决策树

```
输入是原始材料（会议纪要/聊天记录/网页/转写）？
  → 是 → 先按 references/raw-layer.md「提炼流程」抽取要点，再走下面的归档决策
  → 否 ↓

文档是否描述业务目标/流程/架构/重大决策？
  → 是 → 01-项目层
         · 项目背景/目标/里程碑  → 01-项目概览
         · 业务流程/规则/节点    → 02-核心流程
         · 系统架构/技术选型理由  → 03-架构设计
         · 重大决策（ADR）       → 04-决策记录
  → 否 → 文档是否描述技术配置/规范/接口？
           → 是 → 02-技术层
                  · 中间件/连接信息  → 01-中间件配置
                  · 表结构/ER/迁移  → 02-数据库设计
                  · 命名/代码风格   → 03-编码规范
                  · 依赖/版本/License → 04-第三方库
                  · API/错误码      → 05-接口文档
           → 否 → 03-资产层
                  · PRD/需求评审   → 01-产品需求
                  · 设计/详细设计  → 02-技术方案
                  · 用例/测试报告  → 03-测试用例
                  · Bug/原因/修复  → 04-Bug记录
```

## 归档后必做清单

- [ ] 文档已附完整 YAML 头部（6 个字段齐全）
- [ ] 文档已放入目标子目录
- [ ] 目标子目录 `index.md`「文档清单」已追加新行（编号 / 标题 / 状态 / 日期 / 文档）
- [ ] 所属层级 `index.md`「文档清单」已按需补充
- [ ] 若源自原始材料，正文末尾「## 原始资料」小节已写入路径或链接
- [ ] `文档编号` 在三层内全局唯一

## 常见误区

| 误区 | 正确做法 |
|------|----------|
| 把原始会议纪要直接复制到 `01-项目层/` | 先按 `references/raw-layer.md` 提炼，再把提炼后的文档归档 |
| 文档缺少 YAML 头部就归档 | 必须先按 `templates/document.md` 补全元数据 |
| 修改文档后忘记同步 `index.md` | 修改/废弃时同步更新对应 `index.md` 的「文档清单」行 |
| `文档编号` 跨子目录重复 | 编号在三层内全局唯一，建议使用 `DOC-{层级}-{子目录序号}-{序号}` 格式 |
| 原始层文件也建 `index.md` | 原始层不建 `index.md`，详见 `references/raw-layer.md` |
