# 原始层说明（参考）

## 用途

本文件解释"原始层"的概念、与其他三层的关系、存储建议以及提炼流程，供 AI 在处理原始材料或解释架构时按需加载。

> 加载说明：SKILL.md 仅在 Overview 与决策树中提示原始层存在，详细说明放在本文件中以减少主文件体量。

## 什么是原始层

原始层是项目知识的**信息源头**，存放尚未经过结构化提炼的原始资料，包括但不限于：

- 会议纪要（视频会议、线下讨论的记录或转写）
- 客户/用户访谈记录
- 网页资料、行业报告、竞品分析截图
- 聊天记录（群聊、1v1 中的关键讨论）
- 录音/录像转写、白板照片
- 邮件、需求工单、临时草稿

## 与其他三层的关系

```
原始层  ──(提炼)──>  资产层 / 技术层 / 项目层
   │                       ▲
   └──────(引用追溯)────────┘
```

| 维度 | 原始层 | 项目层 / 技术层 / 资产层 |
|------|--------|------------------------|
| 结构化程度 | 低（原始、零散） | 高（结构化、可检索） |
| 是否在 `docs/` 内 | 否（项目自定位置） | 是 |
| 是否需要 YAML 头部 | 否（按来源保持原貌） | 是 |
| 是否需要 `index.md` | 否 | 是 |
| 生命周期 | 短期（提炼后即可归档） | 中长期（持续维护） |
| 引用方向 | 被上层引用 | 引用时记录原始层出处 |

## 存储位置建议

原始层**不强制放在 `docs/` 下**，推荐存放位置（任选其一）：

| 方案 | 适用场景 | 示例 |
|------|----------|------|
| `docs/raw/` | 与正式文档同库但独立目录 | `docs/raw/2026-08-30-产品周会.md` |
| `docs/00-原始层/` | 显式作为正式结构的第 0 层（不计入三层编号） | `docs/00-原始层/2026-08-30-产品周会.md` |
| 仓库独立目录 | 与代码隔离，避免污染文档检索 | `notes/raw/` 或 `meetings/` |
| 外部知识库 | 团队已有 Notion / Confluence / 语雀 | 仅在正式文档中标注外链 |

## 提炼流程

当原始材料需要进入正式文档时，按以下流程操作：

1. **识别主题** — 判断本次提炼的目标层级（项目层 / 技术层 / 资产层）与子目录
2. **抽取要点** — 从原始材料中抽取关键信息（决策、流程、规范、需求、Bug 等）
3. **写入正式文档** — 新建业务文档，按 `templates/document.md` 附带完整 YAML 头部
4. **登记索引** — 在所属子目录的 `index.md`「文档清单」中追加条目
5. **记录原始出处** — 在正式文档的正文末尾添加「## 原始资料」一节，列出原始材料路径或链接，便于追溯

## AI 强制约束

- **不要**把原始材料直接复制粘贴到 `docs/` 三层结构中
- **不要**为原始层下的文件生成 YAML 头部或 `index.md`
- 当用户提供原始材料并要求"整理成文档"时，AI 必须按上述提炼流程生成新的正式文档，而非归档原始材料
- 当用户提供原始材料并要求"归档"时，应先确认是直接归档（→ 原始层存储位置）还是提炼归档（→ 三层结构）

## 推荐子目录（按来源类型）

新建原始层目录时，**推荐**在根目录下创建以下来源类型子目录，便于按主题检索：

| 子目录 | 用途 | 何时使用 |
|--------|------|----------|
| `meetings/` | 会议纪要 | 团队例会、评审会、需求讨论等高频会议 |
| `interviews/` | 用户/客户访谈 | 用户研究、客户调研记录 |
| `web-clips/` | 网页资料 | 行业报告、竞品分析、技术文章收藏 |
| `chat-logs/` | 聊天记录 | 群聊、1v1 中需要追溯的关键讨论 |
| `transcripts/` | 录音/录像转写 | 会议录像、客户访谈音频转写 |
| `misc/` | 其他杂项 | 临时草稿、邮件、工单截图等 |

> 按日期分子目录（如 `2026-Q3/`、`2026-Q4/`）是另一种合法做法，适用于来源类型单一的项目。

## 原始材料文件命名规范

采用 **`YYYY-MM-DD-{来源}-{简短描述}.md`** 格式：

| 段 | 含义 | 示例 |
|----|------|------|
| `YYYY-MM-DD` | 原始材料产生日期 | `2026-08-30` |
| `{来源}` | 来源类型简码 | `meeting` / `interview` / `web` / `chat` / `transcript` / `misc` |
| `{简短描述}` | 中划线分隔的简短描述 | `产品周会`、`用户访谈-王先生` |

完整示例：

- `2026-08-30-meeting-产品周会.md`
- `2026-08-25-interview-用户访谈-王先生.md`
- `2026-08-20-web-AI-竞品分析.md`
- `2026-08-15-chat-订单中心重构讨论.md`

> 该规范用于**指导 AI 与作者为新材料正确命名**，不强制历史材料改名。

## 原始层层说明 README.md 模板

原始层**不建 `index.md`**，但**应建 `README.md`** 作为层说明（这是与三层的关键区别）。AI 在初始化原始层时，直接复制下方代码块到 `docs/raw/README.md`（或项目自定的原始层目录下），并按项目实际情况微调子目录表与命名规范表。

````markdown
# 原始层

> 本目录存放**未经过结构化提炼的原始资料**（会议纪要、聊天记录、网页、转写、草稿等），作为三层结构（项目层 / 技术层 / 资产层）的信息源头。原始材料经提炼后才能进入正式层级。

## 归档范围

本目录用于归档：

- 会议纪要（视频会议、线下讨论的记录或转写）
- 客户/用户访谈记录
- 网页资料、行业报告、竞品分析截图
- 聊天记录（群聊、1v1 中的关键讨论）
- 录音/录像转写、白板照片
- 邮件、需求工单、临时草稿

**不属于**本目录：

- 已整理成正式文档的内容（→ 归档到 `docs/01-项目层/`、`02-技术层/`、`03-资产层/` 对应子目录）
- 代码注释、API 文档（→ 三层结构）
````

### 使用方式

1. 在原始层根目录下创建 `README.md`（**注意不是 `index.md`**）
2. 复制上方模板内容
3. 按项目实际情况：
   - 调整「子目录结构」表格（增删子目录）
   - 调整「文件命名规范」（如增加自定义来源简码）
   - 在「归档范围」一节增删项目
4. 文件命名规范的目的是**让 AI 知道如何在新材料放入时正确命名**，不是强制历史材料改名
