# 原始层说明（参考）

## 用途

本文件解释"原始层"的概念、与其他三层的关系、存储建议以及蒸馏流程，供 AI 在处理原始材料或解释架构时按需加载。

> 加载说明：SKILL.md 仅在 Overview 与决策树中提示原始层存在，详细说明放在本文件中以减少主文件体量。

## 什么是原始层

原始层是项目知识的**蒸馏原料池**，存放尚未经过结构化提炼的原始资料，包括但不限于：

- 会议纪要（视频会议、线下讨论的记录或转写）
- 客户/用户访谈记录
- 网页资料、行业报告、竞品分析截图
- 聊天记录（群聊、1v1 中的关键讨论）
- 录音/录像转写、白板照片
- 邮件、需求工单、临时草稿

### 核心定位：蒸馏原料池

原始层不是"归档废纸篓"，而是知识生产的**上游入口**：

> 丢进去一段会议录音转写，让 Agent 读取后，**自动提炼出 PRD** 塞进 `03-资产层/01-产品需求`，或**自动提炼出 ADR** 塞进 `01-项目层/04-决策记录`。

因此原始层有三条硬性要求：

1. **必须初始化** — 任何模式下都要创建 `docs/04-原始层/`，否则蒸馏链路断掉
2. **原料必须被消化** — 放入原料后，Agent 应主动执行蒸馏流程产出正式文档，而不是只存着
3. **产物必须可追溯** — 每份正式文档都要回链它的原料路径

## 与前三层的关系

```
原始层（蒸馏原料池）──(蒸馏)──>  资产层 / 技术层 / 项目层
   │                                ▲
   └──────────(引用追溯)────────────┘
```

| 维度 | 原始层 | 项目层 / 技术层 / 资产层 |
|------|--------|------------------------|
| 定位 | 蒸馏原料池 | 蒸馏产物（正式知识） |
| 结构化程度 | 低（原始、零散） | 高（结构化、可检索） |
| 是否在 `docs/` 内 | 是（默认 `docs/04-原始层/`） | 是 |
| 是否必须初始化 | ✅ 必须 | ✅ 必须 |
| 是否需要 YAML 头部 | 否（按来源保持原貌） | 是 |
| 是否需要 `index.md` | 否（用 `README.md`） | 是 |
| 生命周期 | 长期留存（原料池持续投料） | 中长期（持续维护） |
| 引用方向 | 被上层引用 | 引用时记录原始层出处 |

## 存储位置

原始层**默认放在 `docs/` 内**，作为第 4 层：

| 方案 | 路径 | 适用 | 默认 |
|------|------|------|------|
| A | `docs/04-原始层/` | 与前三层同库，作为第 4 层 | ✅ 默认 |
| B | 仓库独立目录 | 与代码隔离，避免污染文档检索 | 用户明确要求隔离时 |
| C | 外部知识库 | 团队已有 Notion / Confluence / 语雀 | 仅在正式文档中标注外链 |

> 除用户明确指定外，一律初始化在 `docs/04-原始层/`。

## 蒸馏流程

原始材料进入正式文档的标准流程（Agent 读取原料后自动执行）：

1. **读取原料** — 读取原始层中的新材料（转写 / 纪要 / 聊天 / 网页）
2. **识别产物类型** — 按下方「蒸馏路由表」判定应产出 PRD / ADR / 技术方案 / 踩坑记录等
3. **抽取要点** — 从原料中抽取结构化要点（背景、目标、约束、结论、行动项）
4. **写入正式文档** — 在目标子目录新建文档，按 `templates/document.md` 附带完整 YAML 头部
5. **登记索引** — 在所属子目录的 `index.md`「文档清单」中追加条目
6. **回链原料** — 在正式文档的正文末尾添加「## 原始资料」一节，列出原始材料路径或链接

### 蒸馏路由表

| 原料类型（原始层） | 蒸馏产物 | 默认写入位置 |
|------|------|------|
| 会议录音/转写 | PRD（产品需求） | `03-资产层/01-产品需求/` |
| 会议录音/转写 | ADR（决策记录） | `01-项目层/04-决策记录/` |
| 会议录音/转写 | 技术方案 | `03-资产层/02-技术方案/` |
| 会议录音/转写 | 核心流程 | `01-项目层/02-核心流程/` |
| 用户/客户访谈 | 需求条目（PRD 章节） | `03-资产层/01-产品需求/` |
| 线上问题排查 / 故障复盘 | 踩坑与经验沉淀 | `03-资产层/04-踩坑与经验沉淀/` |
| 评审结论 / 规范共识 | 编码规范 | `02-技术层/03-编码规范/` |
| 数据表/字段讨论 | 数据库设计 | `02-技术层/02-数据库设计/` |
| 接口讨论 | 接口文档 | `02-技术层/05-接口文档/` |

> 一份原料可能蒸馏出多份产物（例如一场评审会同时产出 ADR 与编码规范），这是正常且推荐的。

## AI 强制约束

- **不要**把原始材料直接复制粘贴到 `docs/` 前三层结构中
- **不要**为原始层下的文件生成 YAML 头部或 `index.md`
- **不要**跳过原始层初始化——`docs/04-原始层/` 与 `README.md` 必须创建
- 当用户提供原始材料并要求"整理成文档"时，AI 必须按上述蒸馏流程生成新的正式文档，而非只归档原始材料
- 当用户提供原始材料并要求"归档"时，应先确认是直接归档（→ 原始层存储位置）还是蒸馏产出（→ 前三层结构）
- 蒸馏产物必须回链原料路径，原料文件本身保留在原始层不动

## 推荐子目录（按来源类型）

新建原始层目录时，**推荐**在根目录下创建以下来源类型子目录，便于按主题检索：

| 子目录 | 用途 | 何时使用 |
|--------|------|----------|
| `01-会议记录/` | 会议纪要 | 团队例会、评审会、需求讨论等高频会议 |
| `02-用户访谈/` | 用户/客户访谈 | 用户研究、客户调研记录 |
| `03-网页资料/` | 网页资料 | 行业报告、竞品分析、技术文章收藏 |
| `04-聊天记录/` | 聊天记录 | 群聊、1v1 中需要追溯的关键讨论 |
| `05-录音转写/` | 录音/录像转写 | 会议录像、客户访谈音频转写 |
| `06-其他杂项/` | 其他杂项 | 临时草稿、邮件、工单截图等 |

> 按日期分子目录（如 `2026-Q3/`、`2026-Q4/`）是另一种合法做法，适用于来源类型单一的项目。

## 原始材料文件命名规范

采用 **`YYYY-MM-DD-{来源}-{简短描述}.md`** 格式：

| 段 | 含义 | 示例 |
|----|------|------|
| `YYYY-MM-DD` | 原始材料产生日期 | `2026-08-30` |
| `{来源}` | 来源类型简码 | `meeting` / `interview` / `web` / `chat` / `transcript` / `misc` |
| `{简短描述}` | 中划线分隔的简短描述 | `产品周会`、`用户访谈-王先生` |

完整示例：

- `2026-08-30-meeting-产品周会.md`
- `2026-08-25-interview-用户访谈-王先生.md`
- `2026-08-20-web-AI-竞品分析.md`
- `2026-08-15-chat-订单中心重构讨论.md`

> 该规范用于**指导 AI 与作者为新材料正确命名**，不强制历史材料改名。

## 原始层层说明 README.md 模板

原始层**不建 `index.md`**，但**必须建 `README.md`** 作为层说明（这是与前三层的关键区别）。AI 在初始化原始层时，直接复制下方代码块到 `docs/04-原始层/README.md`（或项目自定的原始层目录下），并按项目实际情况微调子目录表、蒸馏路由表与命名规范表。

> 本目录是项目的**蒸馏原料池**，存放**未经过结构化提炼的原始资料**（会议录音转写、聊天记录、网页、访谈、草稿等）。Agent 读取原料后会自动蒸馏出 PRD、ADR 等正式文档，写入项目层 / 技术层 / 资产层。

## 归档范围

本目录用于归档：

- 会议纪要（视频会议、线下讨论的记录或转写）
- 客户/用户访谈记录
- 网页资料、行业报告、竞品分析截图
- 聊天记录（群聊、1v1 中的关键讨论）
- 录音/录像转写、白板照片
- 邮件、需求工单、临时草稿

**不属于**本目录：

- 已整理成正式文档的内容（→ 归档到 `docs/01-项目层/`、`02-技术层/`、`03-资产层/` 对应子目录）

### 使用方式

1. 在原始层根目录下创建 `README.md`（**注意不是 `index.md`**）
2. 复制上方模板内容
3. 按项目实际情况：
   - 调整「子目录结构」表格（增删子目录）
   - 调整「蒸馏路由」表格（按项目实际产物映射）
   - 调整「文件命名规范」（如增加自定义来源简码）
   - 在「归档范围」一节增删项目
4. 文件命名规范的目的是**让 AI 知道如何在新材料放入时正确命名**，不是强制历史材料改名
