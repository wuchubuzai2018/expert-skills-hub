# 维护规范（参考）

## 用途

本文件集中维护项目文档体系的全局规则，供 AI 在初始化、归档、修改文档时按需加载。

> 加载说明：SKILL.md 仅保留概要，详细规则放在本文件中以减少主文件体量。

## 命名规范

1. **目录名使用中文**，中划线分隔，数字前缀用于排序（如 `01-项目概览`、`04-Bug记录`）
2. **文件名使用英文或中文均可**，但建议保持与目录风格一致
3. **`index.md` 固定命名**，不得改成 `README.md` 或其他名称

## 文档格式

- 使用 Markdown 格式（`.md`）
- 代码示例使用代码块标注语言
- 表格用于并列信息，列表用于序列信息
- 中英文之间建议保留一个空格

## 元数据强制（YAML 头部）

所有非 `index.md` 的业务文档必须包含 YAML 头部，6 个字段：

| 字段 | 必填 |
|------|------|
| `文档编号` | ✅ |
| `标题` | ✅ |
| `类型` | ✅ |
| `状态` | ✅ |
| `日期` | ✅ |
| `作者` | ✅ |

完整字段定义与示例见 `templates/document.md`。

## 索引强制（index.md）

- 每个目录都必须存在 `index.md`（含三层根目录与所有子目录）
- 文档清单表格列固定为：**编号 / 标题 / 状态 / 日期 / 文档**
- 新增/修改/废弃文档时必须同步更新对应 `index.md`

## 变更日志（log.md，可选）

借鉴自 Google OKF 规范（§9），本技能**支持**（但**不强制**）在每个目录放置 `log.md`，用于按日期分组记录该目录范围内的变更历史。

- 模板与启用场景见 `references/directory-structure.md`「可选保留名 `log.md`」一节
- 与 `index.md` 的区别：`index.md` 关注当前状态，`log.md` 关注历史轨迹

## 层级原则

- 上层文档可引用下层文档，禁止反向依赖（项目层 → 技术层 → 资产层）
- 原始层不属于 `docs/`，由项目自行约定存放位置（详见 `references/raw-layer.md`）
- 正式文档可引用原始层材料，并在正文「## 原始资料」中记录出处

## OKF 对齐（可选）

本技能借鉴 Google OKF v0.2 的部分设计，但默认**不启用** OKF 兼容字段，避免过度设计。当用户明确要求"兼容 OKF"时再启用。

| 借鉴点 | 落地形式 |
|--------|----------|
| 单句摘要 | 新增可选 `描述` 字段 |
| 跨切面分类 | 新增可选 `标签` 字段 |
| 规范 URI | 新增可选 `资源` 字段 |
| 来源追踪 | 新增可选 `来源` 字段（与正文「## 原始资料」互补） |
| 新鲜度 | 新增可选 `过期时间` 字段 |
| 目录级变更历史 | 新增可选 `log.md` 保留名 |

完整对比与适配建议见 `references/okf-intro.md`。

## 版本管理

- 文档随代码版本更新，保持同步
- 状态变更（草稿→评审中→现行→已废弃）或内容更新时同步修改 `日期` 字段
- 已废弃文档不删除，建议在文件名加 `-archived` 后缀，并保留在原目录

## 幂等操作

- 重复执行技能时只补充缺失内容，不覆盖已有文件
- 已有 `index.md` 不重写，按需追加新条目
- 已有业务文档不重写，仅在缺失元数据时补全

## AI 强制约束汇总

- 不要为原始层文件生成 YAML 头部或 `index.md`
- 不要把原始材料直接复制到 `docs/` 三层结构
- 不要在 `index.md` 中省略文档清单表格（即使是空目录也要保留空表）
- 不要跨子目录复用 `文档编号`，必须全局唯一
- 不要反向引用（资产层 → 技术层、技术层 → 项目层）

## 违规检查清单

在每次执行后，AI 应自检：

- [ ] `docs/` 下三层结构完整，无遗漏子目录
- [ ] 每个目录都有 `index.md`
- [ ] 每个 `index.md` 都包含文档清单表格
- [ ] 每个业务文档都有完整 YAML 头部
- [ ] `文档编号` 全局唯一
- [ ] 没有把原始材料误归到三层结构中
- [ ] 没有反向引用
