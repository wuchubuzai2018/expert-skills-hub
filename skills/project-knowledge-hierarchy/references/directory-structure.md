# 目录结构（参考）

## 用途

本文件给出 `docs/` 三层结构的完整目录树，供 AI 在初始化或维护项目文档目录时参考。

> 加载说明：SKILL.md 仅保留概述与执行步骤，详细目录树放在本文件中按需加载，以减少主文件体量。

## 三层架构

```
docs/
├─ index.md                       # 顶层总览：三层结构说明、快速导航、维护规范
├─ 01-项目层/
│  ├─ index.md                    # 项目层目录索引
│  ├─ 01-项目概览/
│  │  └─ index.md                 # 子目录索引（带文档清单表格）
│  ├─ 02-核心流程/
│  │  └─ index.md
│  ├─ 03-架构设计/
│  │  └─ index.md
│  └─ 04-决策记录/                # 重大技术/业务决策 ADR
│     └─ index.md
├─ 02-技术层/
│  ├─ index.md                    # 技术层目录索引
│  ├─ 01-中间件配置/
│  │  └─ index.md
│  ├─ 02-数据库设计/              # 表结构、ER 图、索引设计、迁移记录
│  │  └─ index.md
│  ├─ 03-编码规范/
│  │  └─ index.md
│  ├─ 04-第三方库/
│  │  └─ index.md
│  └─ 05-接口文档/
│     └─ index.md
└─ 03-资产层/
   ├─ index.md                    # 资产层目录索引
   ├─ 01-产品需求/
   │  └─ index.md
   ├─ 02-技术方案/
   │  └─ index.md
   ├─ 03-测试用例/
   │  └─ index.md
   └─ 04-Bug记录/
      └─ index.md
```

## 强制约束

- 每个目录（包含每个子目录与每个层级根目录）都必须存在 `index.md` 作为目录索引
- 任何具体业务文档都必须带有 YAML 头部元数据（详见 SKILL.md「文档元数据规范」一节）
- `docs/` 只承载前三层（项目层 / 技术层 / 资产层）及其子目录；原始层由项目自行约定存放位置（详见 `references/raw-layer.md`）

## 可选保留名：`log.md`

借鉴自 Google OKF 规范（§9），本技能**支持**（但**不强制**）在每个目录放置 `log.md`，用于按日期分组记录该目录范围内的变更历史。

### 模板

````markdown
# 变更日志：[目录路径]

## YYYY-MM-DD

- [作者] 新增文档 `DOC-XXX-NN-001-XXX.md`（类型：设计 / 状态：草稿）
- [作者] 更新文档 `DOC-XXX-NN-002-XXX.md` 的「接口示例」一节（状态：草稿 → 评审中）

## YYYY-MM-DD

- [作者] 废弃文档 `DOC-XXX-NN-003-XXX.md`（状态：现行 → 已废弃）
````

### 何时启用

- ✅ 多人协作的项目（变更追溯价值高）
- ✅ 合规/审计场景（必须留痕）
- ✅ agent 大量生产文档（信任机制依赖历史）
- ❌ 个人小项目 / 一次性文档（增加维护成本）

### 与 `index.md` 的关系

| 文件 | 关注点 |
|------|--------|
| `index.md` | 当前状态：哪些文档存在、状态如何 |
| `log.md` | 历史轨迹：哪些文档何时增删改 |

## 子目录职责一览

### 01-项目层

| 目录 | 用途 | 包含内容 |
|------|------|----------|
| `01-项目概览` | 项目概览 | 项目背景、目标、范围、里程碑计划 |
| `02-核心流程` | 核心流程 | 业务流程图、业务规则、关键节点 |
| `03-架构设计` | 架构设计 | 系统架构图、模块划分、技术选型理由 |
| `04-决策记录` | 决策记录（ADR） | 重大技术与业务决策的上下文、选项、结论、影响 |
| `index.md` | 层索引 | 项目层目录结构说明、维护规范、文档清单 |

### 02-技术层

| 目录 | 用途 | 包含内容 |
|------|------|----------|
| `01-中间件配置` | 中间件配置 | 缓存、消息队列、配置中心等服务配置 |
| `02-数据库设计` | 数据库设计 | 表结构、ER 图、索引设计、数据迁移、SQL 规范 |
| `03-编码规范` | 编码规范 | 命名规范、代码风格、注释要求、Git 提交规范 |
| `04-第三方库` | 第三方库 | 依赖清单、版本说明、License 清单 |
| `05-接口文档` | 接口文档 | API 接口定义、请求响应示例、错误码说明 |
| `index.md` | 层索引 | 技术层目录结构说明、维护规范、文档清单 |

### 03-资产层

| 目录 | 用途 | 包含内容 |
|------|------|----------|
| `01-产品需求` | 产品需求 | PRD 文档、功能清单、需求评审记录 |
| `02-技术方案` | 技术方案 | 技术方案设计、详细设计文档、评审记录 |
| `03-测试用例` | 测试用例 | 测试计划、测试用例、测试报告 |
| `04-Bug记录` | Bug 记录 | 历史 Bug 清单、问题原因分析、修复记录 |
| `index.md` | 层索引 | 资产层目录结构说明、维护规范、文档清单 |

### 04-原始层（项目自定）

> 原始层是三层结构的**信息源头**，不属于 `docs/` 三层结构内，但作为第 4 层在此统一登记。子目录与命名由项目自定，下面是推荐做法。详见 [`references/raw-layer.md`](./raw-layer.md)（含完整 README 模板）。

| 目录 / 文件 | 用途 | 包含内容 |
|------|------|----------|
| `README.md` | 层说明 | 归档范围、文件命名规范、与三层关系（注意：不是 `index.md`） |
| `meetings/` | 会议纪要 | 例会、评审会、需求讨论等记录 |
| `interviews/` | 用户/客户访谈 | 用户研究、客户调研记录 |
| `web-clips/` | 网页资料 | 行业报告、竞品分析、技术文章收藏 |
| `chat-logs/` | 聊天记录 | 群聊、1v1 中需要追溯的关键讨论 |
| `transcripts/` | 录音/录像转写 | 会议录像、客户访谈音频转写 |
| `misc/` | 其他杂项 | 临时草稿、邮件、工单截图等 |

**推荐存储位置**：

| 方案 | 路径 | 适用 |
|------|------|------|
| A | `docs/raw/` | 与正式文档同库但独立目录（最常用） |
| B | `docs/00-原始层/` | 显式作为正式结构的第 0 层 |
| C | `notes/raw/` 或 `meetings/` | 仓库独立目录，与代码隔离 |
| D | Notion / Confluence / 语雀 | 外部知识库（仅在正式文档中标注外链） |

**文件命名规范**：`YYYY-MM-DD-{来源}-{简短描述}.md`

| 段 | 含义 | 示例 |
|----|------|------|
| `YYYY-MM-DD` | 原始材料产生日期 | `2026-08-30` |
| `{来源}` | 来源类型简码 | `meeting` / `interview` / `web` / `chat` / `transcript` / `misc` |
| `{简短描述}` | 中划线分隔的简短描述 | `产品周会`、`用户访谈-王先生` |

完整命名示例：`2026-08-30-meeting-产品周会.md`、`2026-08-25-interview-王先生.md`。

## 使用方式

1. 在初始化阶段，AI 按本文件目录树创建 `docs/` 全部目录
2. 在自定义模式下，从本文件选择实际需要的子目录
3. 目录命名需要变更时，应同步更新本文件
