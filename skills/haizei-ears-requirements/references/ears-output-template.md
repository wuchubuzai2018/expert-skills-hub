# EARS 输出模板

该文档用于统一 EARS 需求改写与审查的输出结构，避免每次输出风格不一致，便于评审、追踪和复用。

以下模板中的 EARS 关键字和 `shall` 保留原始英文写法，以确保句式语法准确。

## 预期输出

- 每条规格对应的 EARS 模式判断结果。
- 改写后的规格陈述，必要时拆分为多条独立规格。
- 改写前 / 改写后的对照说明。
- 对模糊点、缺失条件、不可验证表达的审查意见。
- 如用户提供的是一组需求，输出应按条目编号，便于评审和追踪。

## 输出要求

1. 优先保留用户原始业务语义，不擅自补充未经说明的业务规则。
2. 如果原始需求包含多个动作或多个条件，应拆成多条规格，不强行压成一句。
3. 如果关键信息缺失，应明确指出缺失项，例如触发事件、时间约束、失败处理、数量上限。
4. 输出中的 EARS 关键字必须大写，但解释性文字优先使用中文。
5. 若无法确定模式，应先说明判断依据，再给出候选写法，而不是直接武断定稿。

## 中文生产输出补充要求

1. 最终交付给业务方的规格正文，默认使用中文句式和 `应`，不直接输出 `WHEN`、`WHILE`、`IF`、`THEN`、`WHERE`、`shall`。
2. 如果需要保留标准 EARS 形式，应将英文关键词版本放在“模式说明”或“补充说明”中，而不是替代最终正文。
3. 模板中的“改写后规格”默认优先输出中文生产写法。

## 模板 1：单条需求改写

适用于用户只提供一条原始需求，需要完成模式判断、改写和问题识别的场景。

```markdown
## 原始需求
<用户原始描述>

## 模式判断
- 推荐模式：<Ubiquitous / Event-Driven / State-Driven / Optional Feature / Unwanted Behavior / Complex>
- 判断依据：<为什么进入该模式>

## 改写后规格
- <改写后的 EARS 规格>

## 待确认问题
- <缺失的触发条件 / 时间约束 / 失败处理 / 数值上限>
```

## 模板 2：多条需求拆分改写

适用于一句话里包含多个动作、多个异常场景或多个时序阶段，需要先拆分再改写的场景。

```markdown
## 原始需求
<用户原始描述>

## 拆分说明
- 原需求包含 <N> 个独立动作 / 场景，需拆分后分别改写。

## 改写结果
1. <模式名称>
   - 改写后：<EARS 规格>
   - 说明：<为什么单独拆出这一条>

2. <模式名称>
   - 改写后：<EARS 规格>
   - 说明：<为什么单独拆出这一条>

## 待确认问题
- <仍缺失的信息>
```

## 模板 3：审查现有规格

适用于用户给出已有需求或验收标准，需要判断是否符合 EARS 并指出问题的场景。

```markdown
## 待审查原文
<原始规格>

## 审查结论
- 是否符合 EARS：<是 / 否 / 部分符合>
- 主要问题：<模糊词 / 缺少触发条件 / 多动作混写 / 不可验证>

## 改写建议
- <改写后的 EARS 规格>

## 待确认问题
- <仍需业务确认的内容>
```

## 模板 4：带最小术语整理的改写

适用于原始描述跨度较大、主语和对象不够清楚，需要先最小限度梳理术语再改写的场景。

```markdown
## 原始描述
<原始描述>

## 术语 / 角色（最小）
- 用户：<说明>
- 系统：<说明>
- 核心对象：<说明>

## 功能需求（EARS）
- <模式> <改写后的 EARS 规格>
- <模式> <改写后的 EARS 规格>

## 非功能 / 约束（如有）
- <改写后的约束规格>

## 待确认问题
- <缺失的边界或约束>
```

## 输出注意事项

- 如果一句原始需求中包含多个动作，优先用“模板 2”。
- 如果用户明确要求“review”或“审查”，优先用“模板 3”。
- 如果术语混乱、主语不清或对象未定义，先用“模板 4”。
- 如果信息不足以定量化，不要虚构数值，应放入“待确认问题”。
- 若用户要求改写前后对照，保留“原始需求”与“改写后规格”两个区域，不要只给最终结果。

## 实战提示

- 对 PM 原始口语需求，常用“模板 2”或“模板 4”。
- 对验收标准或接口约束，常用“模板 1”或“模板 3”。
- 对 AI 提示词消歧，优先先输出“模式判断 + 改写后规格 + 待确认问题”。
