## 顶部导航（nav）

面向新人友好，避免过于技术化的命名：

```
首页 | 新人指南 | 技术知识 | 业务知识 | 常见问题
```

对应链接：
- 首页 → `/`
- 新人指南 → `/wiki/guide/`
- 技术知识 → `/wiki/tech-wiki/`
- 业务知识 → `/wiki/biz-wiki/`
- 常见问题 → `/wiki/guide/faq/`

## 新人指南专区说明

### guide/index.md — 新人指南入口

内容：
- 简短说明本 wiki 的定位和适合谁读
- 按角色推荐不同的阅读路径（新人开发 / 接手维护 / 模块负责人）
- 按新人阶段推荐阅读顺序（第1天 → 第2天 → 第3-5天 → 第5-7天）
- 链接到各子分类文档

### guide/base/ 基础篇（第一天看的内容）

#### 01_快速上手.md

参考 ltc-system-wiki 的"新人30分钟快速上手"格式：
- 这份文档解决什么问题
- 先记住的 N 个事实（项目做什么、技术栈、主业务主线）
- 当前最需要知道的主线
- 第一小时推荐阅读顺序（总览 → 结构 → 架构 → 实践）
- 如果你要从某个模块开始切入（按模块给入口）
- 新人最常见的误区
- 读完后你应该知道什么（自检清单）

#### 02_阅读指南与接手路线图.md

- 当前文档体系怎么理解（项目级 vs 模块级）
- 按角色阅读路径（新人开发 / 接手维护 / 模块负责人）
- 按目标阅读路径（想知道项目是什么 / 数据怎么组织 / 为什么这样校验）
- 从项目级切换到模块级的方法
- 接手前两天建议阅读安排

#### 03_接手维护关键入口清单.md

- 接手时最先确认的 4 类入口（文档入口/代码分层入口/数据入口/规则入口）
- 按问题类型查入口（接口返回不对/流程状态不对/SQL不对/外部联动异常）
- 按业务域找入口
- 高风险修改前必须补看的文档
- 接手后一周建议完成的认知清单

### guide/setup/ 环境篇（第1-2天）

#### 01_本地环境搭建.md

根据项目分析自动生成：
- 前置依赖（从 pom.xml/package.json/build.gradle 等提取 JDK/Node/数据库版本）
- 一键启动命令（从 Makefile/scripts/package.json scripts 提取）
- 配置文件说明（关键的 application.yml/.env 文件及其作用）
- 常见启动报错及解决（基于代码中的典型配置依赖推断）

#### 02_联调与测试环境.md

- 环境清单（从配置文件中提取的 profile/环境变量）
- 外部依赖 Mock 方式（第三方服务的 Mock 或 stub 配置）
- 数据库初始化（初始 SQL/迁移脚本位置）
- 如何跑测试（测试命令和测试数据准备）

### guide/codebase/ 代码篇（第2-3天）

#### 01_代码导航地图.md

面向"我要改某个功能，该看哪个文件"：
- 按功能找代码（功能 → Controller / Service / 表）
- 按页面找代码（前端路由/页面 → 后端接口 → Service）
- 按数据流找代码（数据从哪来 → 经过哪些处理 → 到哪去）
- 关键类速查表（最常改的 20 个类，每个附一句话说明）

#### 02_核心链路速查.md

面向"我要理解某个操作的完整流程"：
- 按用户操作列出链路（用户点了"提交" → 完整调用路径 3+ 层）
- 每条链路标注涉及的表、消息队列、缓存
- 速查卡片式，每条链路控制在 10 行内

#### 03_调试排查技巧.md

- 日志在哪看（日志配置、日志路径、关键日志关键词）
- 常见问题排查路径（接口 500 → 看哪里、数据不对 → 看哪里）
- 断点建议位置（哪些类/方法值得打断点）
- 数据库排查（常用 SQL 查询模板）

### guide/practice/ 实战篇（第3-7天）

#### 01_第一个改动怎么做.md

面向"我接到第一个需求，从头到尾怎么做"：
- 典型改动示例（比如"新增一个字段"完整步骤）
- 代码修改 checklist（改了 entity 还要改什么：VO、Mapper、XML、前端）
- 提交规范（commit message 格式、分支命名）
- 自测方法（改完怎么验证没问题）

#### 02_常见修改场景指南.md

按场景给出 step-by-step：
- 新增接口 / 新增字段 / 修改业务规则 / 新增定时任务 / 对接外部系统 / 修改审批流程
- 每个场景标注：涉及哪些文件、注意事项、容易遗漏的点

#### 03_提测与上线注意事项.md

- 提测前 checklist
- SQL 脚本规范
- 配置变更规范
- 上线后验证步骤
- 回滚方案

### guide/faq/ 常见问题

#### index.md

动态收集项目中的"非显而易见"的知识点：
- 为什么 XX 要这样设计（从 tech-wiki 07 的问题清单中提炼）
- XX 和 YY 有什么区别（从 tech-wiki 02 术语表中提炼）
- 改了 XX 会影响什么（从调用链分析中提炼）
- XX 在什么情况下会触发（从 biz-wiki 规则中提炼）

## 目录约束

- `docs/index.md` 是 VitePress 站点首页，使用 `layout: home` + hero + features 格式。
- `docs/package.json` 是最小 VitePress 工程入口，包含 `docs:dev`、`docs:build`、`docs:preview` 脚本。
- `docs/wiki/index.md` 是 wiki 总览页，包含阅读指南和文档地图。
- `docs/wiki/.wiki-state/` 是状态目录，不在 VitePress 侧边栏展示。
- `docs/wiki/guide/` 是新人指南专区，面向首次接触项目的人。
- `tech-wiki/` 采用扁平结构，固定 01-07 系列文档。
- `biz-wiki/` 采用域目录结构，每个业务域一个子目录。

## 命名约束

- 技术 Wiki 文件名固定为 `01_系统架构分析.md` 到 `07_架构设计问题清单.md`。
- 业务 Wiki 域目录名使用中文业务口径（如"用户管理"、"订单处理"）。
- 域内文档固定为 `01_业务目标与范围.md` 到 `05_异常与边界.md`。
- 新人指南基础篇固定为 `01_快速上手.md` 到 `03_接手维护关键入口清单.md`。
- 新人指南环境篇固定为 `01_本地环境搭建.md`、`02_联调与测试环境.md`。
- 新人指南代码篇固定为 `01_代码导航地图.md` 到 `03_调试排查技巧.md`。
- 新人指南实战篇固定为 `01_第一个改动怎么做.md` 到 `03_提测与上线注意事项.md`。
- 入口页统一使用 `index.md`。

## 生成顺序建议

按新人实际学习阶段分批生成：

| 批次 | 文档 | 理由 |
|------|------|------|
| 第一批 | guide/base/ 全部 + tech-01 + tech-06 | 新人第一天需要的基本认知 |
| 第二批 | guide/setup/ 全部 + guide/codebase/01 | 有了环境才能看代码 |
| 第三批 | guide/codebase/02-03 + guide/practice/01 | 能调试后开始实战 |
| 第四批 | guide/practice/02-03 + guide/faq/ | 前面文档都有了才能写好场景指南和 FAQ |
| 第五批 | tech-02 到 tech-05、tech-07 | 深度技术分析 |
| 第六批 | biz-wiki 各域 | 业务域文档 |

大项目建议每批 2-3 篇文档并行生成。
